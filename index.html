Reactive Flow Front-End

A runnable example for the pattern paper presented at PLoP 2026.

Reactive Flow Front-End is a design pattern for front-end applications. It divides an application into four roles that talk to each other in one direction only. The screen sends events down, and changes of state come back up as notifications. Because information never takes a shortcut, every screen the user sees can be traced back to the events that produced it.

This page runs the code printed in the paper, a small shopping cart, and shows what happens inside it while you use it. The pattern itself is not simulated. Only the server is, so that you can make it slow or make it fail.

The four roles

Reactive Interface
Draws the screen from the current state and turns each click into an event. It never calls the server and never changes the state itself.
Flow Orchestrator
Receives every event and decides what happens next. It applies the event to the state and, when data is needed, asks the infrastructure for it.
State Modules
Hold the state of the application. Here that is the cart, which is the domain model, and the status of the operation in progress. The state only changes through pure functions, so the same events always give the same state.
Infrastructure Adapters
Talk to the server behind a fixed contract. The rest of the application does not know which address is called or how the answer is formatted.

What to try

  1. Add the notebook to the cart and watch the diagram. The event goes down from the interface, the state turns to loading, the request goes to the server, and two notifications come back up to the screen. The message trace lists all eleven messages with their timing.
  2. Add the discontinued lamp. The server refuses it, the adapter turns the refusal into a handled error, and the cart shows the error without breaking. You can also tick "Fail the next request" and add anything.
  3. In the event history, select an earlier event. The page rebuilds the state by replaying the events up to that point through the paper's reducer.
  4. Slow the animation down or raise the server latency to follow each step at your own pace.
